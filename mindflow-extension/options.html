MindFlow Companion

Impostazioni del motore di riassunto e del comportamento del pannello.

Motore

Il motore comprime i segmenti di chat in checkpoint. Può essere un modello locale (Ollama, LM Studio, llama.cpp, vLLM: gira sul tuo computer, gratis e privato) oppure una API (OpenAI, Anthropic).

Ollama: http://127.0.0.1:11434 — LM Studio: http://127.0.0.1:1234/v1 — llama.cpp: http://127.0.0.1:8080/v1

Per i checkpoint basta un modello piccolo (3B–8B): veloce e gratuito. Per Ollama usa l'ID esatto di ollama list.

«Rileva automaticamente» prova Ollama, LM Studio, llama.cpp, vLLM, Jan, KoboldCpp, GPT4All e text-generation-webui sulle porte predefinite e compila i campi per te. «Prova riassunto» chiede al motore di comprimere un segmento d'esempio: è la verifica END-TO-END che il checkpoint verrà generato dal modello configurato.

Le chiavi restano nel chrome.storage locale del tuo browser: non lasciano mai il computer, tranne verso il provider che scegli. MindFlow non ha alcun server.

Sblocca Ollama (una volta sola)

Ollama, per sicurezza, accetta dal browser solo le pagine su http://localhost. Un'estensione parte da un'origine diversa (chrome-extension://…) e Ollama rifiuta le sue richieste con l'errore 403: per questo la connessione risulta a posto ma ogni riassunto fallisce. Si sblocca una volta per tutte, in tre passi:

  1. Esci da Ollama (icona nella barra delle applicazioni / menu in alto → Esci o Quit). Non basta chiudere la finestra: deve proprio uscire.
  2. Imposta la variabile d'ambiente OLLAMA_ORIGINS con questo valore (apre Ollama alle estensioni di Chrome, Edge, Firefox e Safari):
    chrome-extension://*,moz-extension://*,safari-web-extension://*
    Windows

    Impostazioni di sistema → cerca «variabili d'ambiente» → «Modifica le variabili d'ambiente del tuo account» → Nuova: nome OLLAMA_ORIGINS, valore quello copiato sopra → OK. In alternativa, in PowerShell: setx OLLAMA_ORIGINS "chrome-extension://*,moz-extension://*,safari-web-extension://*"

    macOS

    Terminale: launchctl setenv OLLAMA_ORIGINS "chrome-extension://*,moz-extension://*,safari-web-extension://*"

    Linux

    Con systemd: systemctl edit ollama.service e aggiungi [Service]
    Environment="OLLAMA_ORIGINS=chrome-extension://*,moz-extension://*,safari-web-extension://*"     poi systemctl daemon-reload && systemctl restart ollama.
    Se lo avvii a mano: OLLAMA_ORIGINS="chrome-extension://*,moz-extension://*,safari-web-extension://*" ollama serve

  3. Riavvia Ollama dal menu Start / Launchpad / servizio, poi torna qui e premi di nuovo «Test connessione» e «Prova riassunto».

Nota: la variabile deve essere impostata prima di avviare Ollama — se Ollama era già in esecuzione, non la vede: esci, imposta, riavvia. Se preferisci aprire Ollama a qualsiasi pagina web, usa come valore * (meno restrittivo: scelta tua).

Non riesco a connettermi — guida completa

Prima cosa: lascia perdere il dubbio «endpoint riconosciuto ma motore no» — dietro quasi sempre c'è una porta diversa o un CORS spento, entrambi sistemabili in un minuto. Leggi l'errore che vedi e segui i passi della sezione giusta qui sotto. (Questa guida si apre da sola quando un test non passa.)

  1. La mappa degli errori

    «Motore non raggiungibile» → il server non è avviato oppure la porta è sbagliata · «Errore 403» → il server rifiuta le richieste dell'estensione (CORS) · «model not found / modello assente» → il nome del modello non combacia · «risposta priva di contenuto» → il modello è muto (file corrotti o disco esterno).

  2. LM Studio (porta + CORS: il caso più comune)
    1. Apri LM Studio → scheda Developer (Sviluppo) → Start Server. Il server deve restare acceso mentre usi MindFlow.
    2. Guarda l'indirizzo mostrato lì accanto: è l'endpoint VERO, porta compresa (es. http://127.0.0.1:1235/v1). LM Studio parte sulla 1234 ma, se la trova occupata, sceglie da solo la successiva (1235, 1236…): è il motivo classico per cui «l'endpoint sembrava riconosciuto ma il motore non rispondeva». Incolla quel valore identico nel campo Endpoint base — o sbaglia pure: «Test connessione» corregge la porta da solo cercando il server sulle porte vicine.
    3. Nelle impostazioni del server attiva Enable CORS: senza di esso il test può collegarsi ma ogni riassunto riceve un 403.
    4. Carica il modello e copia la chiave esatta dall'elenco (es. lmstudio-community/Qwen3.5-9B-abliterated-GGUF): puoi anche scrivere «qwen3.5 9b abliterated» a mano, il campo si corregge da solo al primo test.
  3. Ollama
    1. Avvia il server: nel terminale ollama serve (su app desktop: apri l'app, il server parte da solo). Porta predefinita http://127.0.0.1:11434 — senza /v1 (se lo incolli, lo tolgo io).
    2. Nome del modello esatto con ollama list (es. gemma3:4b, non «gemma»).
    3. Se vedi 403: è il blocco estensioni di Ollama — segui la guida «Sblocca Ollama» (qui sopra, si apre da sola): variabile OLLAMA_ORIGINS + riavvio completo.
  4. Controlli generali (tutti i motori)
    1. URL in http:// (non https), senza barra finale; per i server OpenAI-compatibili finisce in /v1.
    2. Premi «Rileva automaticamente»: sondea Ollama (11434–11437), LM Studio (1234–1237), llama.cpp, vLLM, Jan, KoboldCpp, GPT4All e compila i campi da solo.
    3. Antivirus/firewall aziendali possono filtrare le porte locali: prova 127.0.0.1 al posto di localhost (o viceversa: su alcuni Mac/IPv6 risponde solo uno dei due).
    4. Se due motori girano insieme (es. Ollama e LM Studio), quello giusto si sceglie in «Tipo di motore»: «Rileva automaticamente» vede entrambi.

Cosa fa MindFlow da solo, senza che tu faccia nulla: alla prima impostazione dell'endpoint verifica il collegamento; se la porta scritta non risponde ma un server identico è attivo su una porta vicina, la corregge e la salva; il nome del modello si corregge da solo al test; il 403 viene spiegato con la cura giusta. Tu resta solo sull'ON/OFF del server e sulla porta mostrata dalla sua scheda Developer.

Comportamento

Il pannello non si apre né costruisce nulla da solo: premi «Costruisci il grafo» quando vuoi. Il pulsante raccoglie la conversazione (scorrimento compreso), il motore la divide in capitoli semantici e comprime ogni capitolo in un checkpoint. La pillola laterale mostra solo il contatore dei messaggi letti.
